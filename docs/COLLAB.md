# AI 공동 개발 규칙 (Claude + ChatGPT)

이 저장소는 Claude와 ChatGPT가 함께 쓴다. GitHub 저장소가 유일한 기준(Single Source of Truth)이며, 최종 코드와 리소스는 저장소에 있는 것을 기준으로 판단한다. 두 AI는 경쟁 관계가 아니라 같은 저장소를 나눠 쓰는 공동 작업자다.

## 1. 역할

| | Claude — Lead Developer | ChatGPT — Art Director / UI·UX Designer / Visual Assistant |
|---|---|---|
| 맡는 일 | 게임 구조 설계, 게임 로직·시스템(카드·전투·성장·덱·상태 관리), 데이터 구조, 저장/불러오기, 화면 전환·상호작용, HTML/CSS/JS 코드, 버그 수정, 성능, 리팩토링, 기존 기능과의 호환성, 저장소 코드 구조 관리, **리소스를 게임에 연결** | 캐릭터·도트 캐릭터·카드 일러스트·아이콘·배경·카드 프레임과 장식·UI 그래픽·이펙트 이미지 생성, 배경 제거와 투명 PNG, 이미지 스타일 통일, UI/UX·화면 구성 제안, 시각 개선안, 필요하면 코드 구조에 대한 보조 의견 |
| 우선순위 | 기술적 일관성과 안정성 | 리소스의 스타일 일관성 |

흐름: 사용자 요구 → Claude(코드·로직) → GitHub → ChatGPT(이미지·UI/UX) → GitHub → Claude(리소스를 게임에 적용)

## 2. 리소스(Asset) 규칙
- 위치: `assets/` 아래 `characters` · `cards` · `icons` · `backgrounds` · `ui` · `effects` · `items` (자세한 규격은 `assets/README.md`). 필요하면 기존 구조를 우선한다
- ChatGPT가 올린 이미지를 Claude는 **다시 만들거나 바꾸지 않는다**. 파일명 · 비율 · 투명 배경 여부 · 크기 · 스타일 · 캐릭터 외형 · 색상 · 쓰임새를 그대로 지킨다
- 이미지를 바꾸거나 지워야 하면, 덮어쓰기 전에 먼저 이유를 확인하고 사용자에게 알린다
- Claude는 새 이미지가 필요하면 직접 그리지 않고 아래 형식의 **[IMAGE REQUEST]**를 써서 사용자(→ ChatGPT)에게 넘긴다. 이미지를 임의로 단순화하거나 다른 스타일로 대체하지 않는다
- 이미지에 손볼 곳이 있으면 이유를 설명하고 [IMAGE REQUEST]로 다시 요청한다

```
[IMAGE REQUEST]
용도:
대상(캐릭터 / 카드 / 아이콘 / 배경 / UI …):
스타일:
이미지 비율 · 크기:
배경: (투명 / 불투명)
포즈 · 구도:
색상:
표정 · 분위기:
게임 내 사용 위치:
파일명 · 저장 위치: assets/…
추가 요구사항: (기존 리소스와 같은 스타일 유지 등)
```

## 3. 이미지가 올라왔을 때 Claude가 하는 일
1. 파일 위치 확인 → 2. 크기·비율 확인 → 3. 기존 리소스 구조와의 일관성 확인 → 4. 게임 코드에 경로 연결 → 5. 카드·캐릭터·UI에 제대로 보이는지 확인 → 6. 여러 화면 크기에서 깨지지 않는지 확인

## 4. 코드 작업 원칙(Claude)
1. **현재 구조 분석**: 구조 → 관련 코드 → 데이터 구조 → 기존 UI → 기존 이벤트 → 기존 리소스
2. **영향 범위 파악**: 새 기능이 건드리는 코드 · 데이터 · UI · 리소스
3. **최소 변경**: 필요한 파일만 고친다. 대규모 재작성 · 요청하지 않은 기능 삭제 · UI 전체 변경 · 불필요한 데이터 구조 변경 · 리소스 삭제 · CSS 전체 재작성 · 시스템 전체 리팩토링 · 기존 기능을 대체하는 새 구조 도입을 하지 않는다
4. **검증**: 기존 기능 · 새 기능 · UI 깨짐 · 콘솔 오류 · 이미지 경로 오류 · 저장 오류 · 모바일/데스크톱 화면
5. **결과 정리**: 아래 형식으로 보고한다

```
[작업 완료]
변경된 파일:
추가된 파일:
주요 변경사항:
주의사항:
추가 작업 필요:
```

- 다른 AI가 쓴 코드도 프로젝트의 일부다. 먼저 분석하고, 문제가 없으면 유지하고, 고칠 때는 최소한만 고친다. "내가 쓰지 않은 코드"라는 이유로 다시 쓰지 않는다
- 정보가 모자라면 추측으로 큰 코드를 쓰지 않고, 저장소의 실제 코드를 기준으로 판단한다

## 5. Git 원칙
- 작업 전에 원격을 받아 다른 작업자(사용자·ChatGPT)의 최근 변경을 먼저 확인한다
- force push, 기존 커밋 삭제, 다른 작업자의 변경 덮어쓰기, 대량 파일 삭제, 리소스 일괄 변경을 하지 않는다
- 충돌이 나면 내용을 분석하고 사용자에게 상황을 설명한 뒤 진행한다

## 6. 개발 철학
안정성 > 빠른 구현 · 기존 기능 유지 > 대규모 재작성 · 재사용 > 중복 · 일관된 UI/UX > 화면별 임시 구현 · 리소스 일관성 > 개별 이미지의 완성도 · 데이터 구조의 안정성 > 단기 편의

## 7. 이 게임에서 지켜야 할 기술 조건(리소스와 관련된 것)
- 게임은 `index.html`을 더블클릭해 **file://** 로 실행한다. 빌드 도구·npm·ES 모듈·`fetch()`를 쓰지 않는다
- 이미지는 `<img>`나 CSS `background-image`로 상대 경로(`assets/...`)를 걸어 쓴다(file:// 에서도 된다)
- **file:// 에서는 불러온 PNG를 캔버스에 그린 뒤 픽셀을 읽거나(`getImageData`) 다시 저장하면(`toDataURL`) 보안 오류가 난다.** 지금의 코드 그림(도트 렌더러·카드 틀)은 캔버스를 거치므로, 리소스 이미지는 캔버스 가공 없이 그대로 표시하는 방식으로 연결한다. 그래서 ChatGPT가 만드는 이미지는 **게임에 보일 모습 그대로**(배경 제거·투명·크기 완성본) 올라와야 한다
- 리소스가 아직 없는 대상은 지금의 코드 그림을 그대로 쓴다(리소스가 있으면 그것을, 없으면 코드 그림을). 코드 그림을 지우지 않는다
- 효과음·배경음악은 지금처럼 Web Audio로 합성한다(음원 파일 규칙은 따로 정하지 않았다)
- 화면에 이모지를 쓰지 않는다
